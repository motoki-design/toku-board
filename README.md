# toku-board — 解く 案件ボード（定例会議用）

古民家再価値化事業「解く」（TOKU）の定例会議で開くダッシュボード。
**合言葉を入れないと中身が見えない**（ページに埋まっているのは暗号文だけ）。

- 公開URL: https://motoki-design.github.io/toku-board/

## 画面

| タブ | 中身 |
|---|---|
| **案件** | 解くの案件を定例で見る順に7区分。期限の近い順・停滞の可視化・クローズの記録 |
| **営業・広報** | 内覧会の予約状況／PR TIMESリリース／メディア掲載実績／HPアクセスの主要指標 |

## データの持ち方

| 層 | 置き場 | 中身 | 更新 |
|---|---|---|---|
| **案件** | 案件マスタ（GSheet） | 状態・次アクション・期限・直近の動き | マスタを直す→ページの「↻ 更新」で即反映（再ビルド不要） |
| **予約** | 予約一覧（GSheet・非公開） | 申込の集計と匿名項目 | `node refresh.js` → `node build.js` |
| **広報（HP）** | HPアクセス分析ダッシュボード | セッション・自社導線・リリース一覧 | 同上 |
| **それ以外** | `payload.json`（非公開・リポジトリ外） | 区分／未採番案件／クローズ／メディア掲載／電話問い合わせ | 手で編集 → `node build.js` |

**平文データ（`payload.json`）はこのリポジトリに置かない。** 置き場と鍵の場所は社内の運用メモを参照（このリポジトリには書かない）。

## 更新の手順

### 定例の前に（予約と広報を最新にする）
```
node refresh.js                      # 予約シート＋HPアクセスを読んで payload.json を更新
TOKU_PASS='合言葉' node build.js      # 暗号化して index.html を生成
git add index.html && git commit -m "更新" && git push
```

### 案件の状態・次アクション・期限を変えたい
→ **案件マスタ（GSheet）側を直す。** このリポジトリは触らない。

### 合言葉を変えたい
→ 新しい合言葉で `build.js` を流し直して push する。

## 環境変数

| 変数 | 用途 |
|---|---|
| `TOKU_PASS` | 合言葉（`build.js`） |
| `TOKU_SA` | サービスアカウント鍵のパス（`refresh.js`） |
| `TOKU_PAYLOAD` | `payload.json` のパス |
| `TOKU_RESV_SHEET_ID` | 予約シートのID（`refresh.js`） |

**いずれも値はリポジトリに書かない。** 各端末のローカル設定として渡す。

## 予約データの扱い

`refresh.js` は集計と匿名項目（希望日・時間帯・人数・業種・検討の状況・認知経路・来場方法・関心）だけを取り出す。
**連絡先や氏名は payload.json に入れない。** 必要なときは回答シートを直接見る。

テスト申込は `refresh.js` の `CUTOFF`（2026-08-01）より前の行を落として除外している。

## 暗号の仕様

PBKDF2-SHA256（250,000回）で合言葉から鍵を導出し、AES-256-GCM で `payload.json` を暗号化。
ブラウザ側は WebCrypto で復号する。ライブラリは使っていない。
一度開くと `sessionStorage` に合言葉を持つのでリロードしても再入力は要らない。タブを閉じれば消える。

**この合言葉が守るもの**：予約集計・広報実績・未採番案件・区分と停滞フラグ。

## 認証情報

`refresh.js` はサービスアカウントで予約シートを読む（読み取り専用）。
**鍵の実体も、その置き場も、このリポジトリには書かない。** 環境変数 `TOKU_SA` で渡す。

## 既知の注意

- マスタの列名（`種別／案件番号／業務名／主担当／工期／備考／関連リンク／関与メンバー／状態／次アクション／期限／直近の動き／更新日`）を見出し名でマッピングしている。**マスタ側で列名を変えるとページが空になる。**
- `toku` に書いた番号がマスタに見つからない場合、ヘッダに「⚠ マスタに見つからない番号」と出る。
- `refresh.js` はHPアクセス分析ダッシュボードの `window.__GA_DATA__` を読む。先方のページ構造が変わると失敗して、その旨を出す（payload の古い値は残る）。
- Node 22 の標準機能だけで動く（外部パッケージなし）。

## このリポジトリの履歴について

2026-09-07 に**履歴ごと作り直した**。理由＝2026-09-02 の初回公開時、暗号化前の平文 `index.html` が1コミット分だけ公開状態になり、枝から外したあとも SHA 指定で参照できる状態が残っていたため。
**公開リポジトリでは、いまのファイルが安全でも、履歴に平文が残る。** 公開・公開範囲の拡大の前には、作業ツリーと `git log -p --all` の両方に秘匿語の grep をかける。
